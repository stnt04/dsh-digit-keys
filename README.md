给 DeepSeek Harness Web GUI 的**提问卡片**（`ask_user_question`）加数字键操作，并把要按的数字显示出来。

**权限请求面板与计划审批保持原生**：本插件不触碰它们。

只装一个 bundle：

| 插件 | 替换的内置行 | 作用 |
|---|---|---|
| 仓库根（`package.json`） | `ui-user-questions` | 提问卡片数字选择、`Enter` 确认、`Space` 跳过 |

## 按键语义

### 提问卡片

| 键 | 行为 |
|---|---|
| `1`–`9` | 选择对应选项（**暂存，不前进**）；多选题则切换勾选 |
| `Enter` | 确认当前题：非末题 → 下一题；末题 → 提交整批 |
| `Space` | 跳过当前题：非末题 → 下一题；末题 → 提交整批 |
| 鼠标点击 | **保持原样**（单选点击后自动跳下一题） |
| 自定义答案框内 | 数字与空格正常输入；`Enter` = 下一题 / 提交（沿用内置行为） |

### 保持原生的界面

- **权限请求面板**（`ui-approval` / `ApprovalPanel`）：原始按钮与快捷键，`Enter` = 允许一次、`Esc` = 拒绝，没有数字键；
- **计划审批**（`plan-review` / `PlanReviewPanel`）：独立的计划面板，按上游的「同意执行 / 要求修改」按钮操作，没有数字键。

## 生成方式

`src/` 下的每份 fork 都是独立的 `window.__ModuleLoader__.load({...})` 模块，各自声明 `module`/`exports`/`css`/`tagId`/`apply`/`inject`。生成脚本把每个 factory 主体**各自包进一个 IIFE**（主体本来就以 `return module.exports` 结尾，内部一行都不用改），外层模块再组合它们的 `apply` 与 `inject`：

```js
// 多个 half 时（同名声明互不干扰）
const inject = [...new Set([...halfA.inject, ...halfB.inject])];
return { inject, apply(ctx) { halfA.apply(ctx); halfB.apply(ctx); } };
```

当前只有 `questionsHalf` 一个 half，脚本按同一形状生成。**上游升级后重新对齐**：改 `src/` 里对应的 fork，然后

```
node tools/build-combined.mjs
```

脚本会把 CRLF 归一为 LF，因此 Windows 上的 `git checkout` 不会导致重新生成失败。（本仓库本地设置了 `core.autocrlf false`，仅为工作副本配置，不在提交内。）

## 已知限制与风险

- **只覆盖提问卡片**：权限请求与计划审批保持上游行为，不受本插件影响，也没有数字键。
- **依赖 Harness 客户端模块表**：fork 仍 `require` `@deepseek-ai/dsh-client-ui-primitives` 与 `@deepseek-ai/dsh-client-store`；上游改这些包或改卡片内部结构时需要重新对齐 `src/`。
- **禁用了内置行**：patch 把 `ui-user-questions` 置为 `disabled: true`。卸载前请恢复该条，否则提问卡片界面会消失（权限面板不受影响）。
- **上游语义保留**：多选题「自定义文本 + 勾选」的组合行为沿用上游。
